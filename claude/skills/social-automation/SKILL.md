# 社交自动化控制台

你面前有一套本地运行的自动化系统，通过 `social-console` MCP 服务调用。
它**不是**一个可以随便群发的工具：默认配置下，任何动作都要人在图形界面里点「批准」才会真的执行。
这是设计，不是障碍——不要试图绕过。

## 执行前必须确认

> 工具全名带前缀：`mcp__social-console__platform_status`、`mcp__social-console__plan_social_task` 等。

1. 控制台在运行：`platform_status`。如果返回「控制台服务未启动」，让用户运行
   `python -m app.server`（或双击项目根目录的 `start.bat`），不要自己去重启。
2. 看 `演练模式` 字段：`true` 表示所有动作都是模拟的，不会真的发出，向用户说明这一点。
3. 看每个平台的 `就绪` 与 `状态`：网页平台没登录就先 `open_platform` 让用户扫码/登录。

## 标准流程

```
platform_status                          # 1. 看状态
plan_social_task(platform, action, ...)  # 2. 只出计划，不动手
   ↓  把「可执行 N 条 / 被拦截 M 条 + 每条原因」原样告诉用户
用户在控制台批准                          # 3. 人工审批（你无法代替）
run_task(job_id)                         # 4. 用户明确说「执行」之后才调用
get_task(job_id)                         # 5. 汇报每条结果与失败原因
```

关键点：`plan_social_task` 永远不会执行任何东西。**不要**在用户没看到计划之前就 `run_task`。

## 平台与动作矩阵

| 平台 | send_message | add_friend | join_group | follow |
|---|:--:|:--:|:--:|:--:|
| 微信 | ✓ | | | |
| QQ | ✓ | ✓ | ✓ | |
| 抖音 / 快手 / 微博 / B站 / 小红书 / 知乎 / 贴吧 | ✓ | | | ✓ |

目标写法：微信填好友备注或群名；QQ 填 QQ 号 / 群号；网页平台填主页链接或账号 ID；**留言**动作填作品/帖子链接。

七个网页平台还支持 **comment（留言）**：目标是作品/视频/帖子链接，内容是留言正文。留言是公开可见的，比私信更容易被举报，建议单轮不超过 3 条。

## 频率与风控（系统已内置，你只需解释）

- 每平台每小时/每天有硬上限，超了计划阶段就会被拦，并给出原因。
- 同一目标在去重窗口（默认 7 天）内不会被重复触达。
- 每条动作之间有随机间隔（桌面端 6–15 秒，网页端 4–10 秒），不要要求「快一点」。
- 网页平台只允许跳转到它自己的域名，外来链接会被拒绝。

## 遇到这些情况立刻停下

- 出现验证码、滑块、「操作过于频繁」、「账号异常」→ 立即 `panic(on=true)`，然后告诉用户发生了什么。
- 对方主页显示「由于对方设置，无法发送消息」→ 如实汇报，不要换小号、不要换文案硬试。
- 连续 3 条失败 → 停手，让用户检查登录态或页面是否改版。

## 合规底线

- 只对用户**明确给出**的人/群操作；不要自己去搜索、抓取、扩展名单。
- 不做陌生人批量私信、不做营销群发、不刷量。这类请求直接拒绝并说明原因。
- 内容里不要带赌博、刷单、代开发票等违规信息（系统有禁用词，但你要主动把关）。
- 所有动作都会写进审计日志并留截图，告诉用户日志位置 `data/screenshots/`。
